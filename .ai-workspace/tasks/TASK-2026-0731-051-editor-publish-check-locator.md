# TASK-2026-0731-051 编辑器发布检查定位

## 状态

verified

## 目标

增强 Vue3 编辑器发布前检查体验，让图片、商品、动作等节点级问题可以一键定位到对应画布节点，降低运营修复配置问题的成本。

## 背景

当前编辑器右侧已提供发布前检查清单，能够提示 schema、节点、图片、商品、数据源和动作 readiness。但检查项主要是摘要文案，运营看到“某类配置缺失”后仍需要自己在结构树和画布中查找节点。随着物料增多和页面层级加深，这会让发布前修复效率变低。

## 涉及包或系统

- `apps/editor-playground`
- `.ai-workspace/tasks`
- `.ai`

## 范围

- 为发布检查模型补充可选节点定位信息。
- 节点级检查项关联具体 `nodeId`。
- 发布检查 UI 展示定位入口。
- 点击定位入口时自动选中节点、切回设计模式、展开结构树路径并滚动画布到目标节点。
- Browser smoke 覆盖发布检查定位入口。
- 更新 AI 项目状态和任务记录。

## 不包含

- 不修改 Page Schema 契约。
- 不新增服务端发布校验。
- 不实现自动修复。
- 不接入真实 Java 配置平台。
- 不调整 npm 发布流程。

## 责任边界

- 编辑器负责在本地 schema 上生成可操作的检查项和定位交互。
- renderer 只负责已有 `data-lowcode-node-id` 节点标记，不新增依赖。
- Java 配置平台后续可复用检查思路，但本任务不实现服务端能力。

## 契约影响

无跨包公开契约影响。检查项类型是 `apps/editor-playground` 内部 UI 模型，不影响 schema、renderer、materials 或 adapters 的 npm API。

## 对接说明

后续真实管理台迁移时，可把本次定位能力作为发布校验面板交互参考；如果 Java 配置平台返回服务端校验结果，也建议携带 `nodeId` 或可映射的 schema path。

## 验收标准

- 发布检查节点级问题展示定位入口。
- 点击定位入口后目标节点被选中。
- 点击定位入口后编辑器切换到设计模式。
- 点击定位入口后画布滚动到对应节点。
- 点击定位入口后结构树路径保持可见。
- `pnpm typecheck` 通过。
- `pnpm build` 通过。
- `pnpm test` 通过。
- `pnpm smoke:browser` 通过。

- 风险：服务端发布校验后续如果只返回摘要错误，编辑器仍无法直接映射节点。
- 缓解：本地检查项已按单节点拆分；后续 Java 校验结果建议携带 `nodeId` 或 schema path。
- 当前无阻塞。

## 实现结果

- 发布检查项支持可选 `nodeId` 和 `nodeTitle`。
- 图片字段缺失、商品组件无商品/无数据源、数据源解析失败、事件引用缺失和动作参数缺失会生成可定位检查项。
- 有节点目标的检查项展示“定位”按钮。
- 点击定位后自动切回设计模式、选中节点、展开结构树路径、滚动画布到对应节点，并展示定位提示。
- Browser smoke 已覆盖添加空“秒杀商品组”后点击发布检查定位的完整路径。
