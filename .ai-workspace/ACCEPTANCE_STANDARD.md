# 统一验收标准

## 验收维度

每个正式工作项必须从四个维度验收。

## 产品验收

确认目标路径成立：

- 编辑器或运行时使用路径清楚。
- loading、error、empty 和 fallback 状态可描述。
- 运营配置错误不会导致不可恢复白屏。
- 跨端能力有平台边界说明。

## 工程验收

确认实现符合架构边界：

- 没有绕过 schema/core/renderer/materials/adapters 的职责边界。
- 没有引入未说明的新依赖。
- 类型、schema 或数据结构变更有兼容说明。
- renderer 不依赖 editor。
- materials 不依赖业务项目内部代码。

## 测试验收

确认验证有记录：

- 类型检查通过。
- 构建通过。
- 关键 runtime 或 schema 逻辑有测试计划或已覆盖。
- npm 包 dry-run 或发布预演符合预期。
- 无法自动化验证时，写明人工验证步骤和结果。

## 发布验收

确认上线可控：

- 明确是否影响 npm 发布。
- 明确是否影响 schema 兼容性。
- 明确是否影响 H5 接入。
- 明确是否需要 GitHub tag 或 release。
- 明确回滚方式和 smoke check。

## 最低验收口径

一个任务不能只以“代码写完”作为完成标准。至少要有：

```text
实现结果
验证命令
验证结果
风险说明
状态更新
```
