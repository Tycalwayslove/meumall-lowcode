# 统一工作项结构

## 目的

工作项是 AI 和人类协作的最小正式单位。它记录目标、边界、上下文、契约、验收、测试、发布和责任归属。

## 命名

工作项文件使用以下格式：

```text
TASK-YYYY-MMDD-NNN-短标题.md
```

示例：

```text
TASK-2026-0731-001-schema-v1-contract.md
```

## 必填字段

每个工作项必须包含：

- 标题
- 状态
- 目标
- 背景
- 涉及包或系统
- 范围
- 不包含
- 责任边界
- 契约影响
- 对接说明
- 验收标准
- 验证命令
- 发布影响
- 风险和阻塞
- 变更记录

## 任务粒度

一个工作项应该能在一次清晰的开发周期内完成。满足以下任一条件时，应拆分：

- 同时改变 schema、renderer、editor 和发布流程。
- 验收标准超过十条。
- 涉及两个以上外部系统。
- 无法在一份实现计划中清楚表达步骤。

## 契约字段

如果任务涉及跨包或跨系统交互，必须写明：

- 提供方。
- 消费方。
- 契约文档路径。
- 是否向后兼容。
- 是否需要迁移。
- 是否需要灰度或双版本兼容。

## 验收字段

验收标准必须可验证。推荐写：

- `pnpm typecheck` 通过。
- `pnpm build` 通过。
- npm dry-run 能包含预期文件。
- schema 变更提供迁移说明。
- renderer 对未知物料显示 fallback，不导致整页白屏。
